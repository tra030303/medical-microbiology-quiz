## 1차·2차 시험 공간

2026-11-23 요청부터 새로 첨부하는 강의록과 새 문제는 **2차 시험**에 추가합니다. 사용자가 1차 복습·수정이라고 지정하면 기존 1차에 반영합니다. 기존 1차 문제를 2차로 복사하거나 임의로 재분류하지 않습니다.

- 상단 `1차 시험`·`2차 시험` 탭으로 전환합니다. 기존 주소는 1차를 유지하고 `?exam=2#/home`은 2차를 바로 엽니다.
- 1차는 기존 `data/`의 문제·분류·OX·CBL·해설과 기존 저장 키를 그대로 사용합니다. 2차는 `data/exam-2/`의 해당 파일을 사용합니다. `src/exam-data.js`가 현재 시험의 자료만 연결합니다.
- 객관식, 족보, OX, CBL, 선지별 해설과 AI 검토 기록을 시험별로 관리합니다. 각 시험 안에서도 족보와 만든 문제는 기존처럼 섞지 않습니다.
- 2차의 강의 분류는 강의록을 검토한 뒤 `data/exam-2/categories.js`에 등록합니다. 2차 문제는 `data/exam-2/chat-questions.js`, OX는 `ox-index.js`·`ox-questions.js`, CBL은 `cbl-index.js`·`cbl-guides.js`, 별도 해설·검토는 `choice-notes.js`·`review-notes.js`에 넣습니다.
- 가져오기 스크립트는 2차에 **`--exam 2`를 반드시 지정**합니다. 예: `node scripts/import-chat-bundle.mjs /absolute/path/new-questions.json --exam 2 --bank generated --dry-run`. 생략 시 이전 동작인 1차를 사용합니다. 미리보기 검증 후 같은 명령에서 `--dry-run`을 제거합니다.
- 풀이 기록, 사용자 문제, 정답 재지정, 오답, 북마크, OX 진도, 백업·복원·초기화는 현재 시험에만 적용합니다. 1차 저장 키 `immunote.study.v1`을 마이그레이션하거나 지우지 않습니다. 2차 키는 `immunote.study.exam2.v1`입니다.
- 백업에 `exam: 1` 또는 `exam: 2`를 표시하고 다른 시험 탭에서는 복원하지 않습니다. 시험 표시가 없는 기존 백업은 1차 백업으로 복원합니다.

새 문제 파일이나 강의 자료를 이 채팅에 첨부하고 원하는 작업을 말하면, assistant가 내용을 검토하여 저장소에 반영합니다. 사이트에 같은 파일을 다시 올릴 필요는 없습니다. 첨부만으로 백그라운드 게시가 일어나는 감시 서비스는 아니며, 각 요청에 대한 검토·반영·게시 작업입니다.

## 업데이트 흐름

1. 첨부 파일에서 문제를 읽거나, 요청한 범위의 문제를 만듭니다.
2. `족보 기출(past)`과 `만든 문제(generated)`를 명시적으로 지정하고 족보 강의 분류에 연결합니다. ‘기출 응용’이라는 제목이나 태그만으로 만든 문제를 실제 기출로 분류하지 않습니다.
3. 보기·정답 대응과 출처를 검토합니다. 확인할 수 없는 족보 답은 추측해서 넣지 않습니다.
4. 원문 정답은 보존하고, assistant의 정정 제안·해석·불확실성은 별도 검토 의견에 기록합니다.
5. 질문 데이터 검증과 채점 테스트를 통과한 뒤, 승인된 GitHub 저장소에 변경을 반영합니다.
6. GitHub Actions가 성공적으로 배포한 주소를 확인하여 안내합니다. 앞으로도 같은 주소를 사용합니다.

GitHub 계정 연결, 저장소 쓰기 권한, Pages 게시 설정이 준비되어 있어야 실제 게시가 가능합니다. 페이지 게시 범위와 저장소 공개 범위는 계정 및 GitHub 요금제에 따라 달라지므로 게시 전에 확인합니다.

## 출제 범위와 선지 구성

사용자는 실제 시험이 감염·면역 전 범위에서 출제된다는 점을 반영하기를 요청했습니다. 앞으로는 핵심 개념 확인 문항과 여러 강의를 비교하는 통합 문항을 함께 구성합니다.

- 문항의 주된 학습목표와 강의 분류를 유지하면서, 일부 문항의 선지에는 다른 강의와 후반 강의의 개념을 포함합니다. 현재 강의 및 그 이전 순서로 선지 범위를 제한하지 않습니다.
- 아직 첨부하지 않은 강의의 주제도 검증된 교과 지식으로 활용할 수 있습니다. 실제로 확인한 공인 자료·원저를 보완 출처로 명시하고, 열람하지 않은 교수님의 강의 내용이나 강조점으로 표시하지 않습니다. 이후 해당 강의록이 첨부되면 이를 대조합니다.
- 비슷한 임상상, 병원성 인자, 검사 결과, 치료 기전처럼 구별할 이유가 있는 대안을 사용합니다. 다른 강의의 균 이름만 붙이거나 무관한 대안을 채우지 않습니다. 대안의 실제 개념과 이 문항에서 맞지 않는 이유를 선지별로 설명합니다.
- 통합 문항에는 `전범위 통합` 태그를 붙입니다. 검색으로 모아 풀 수 있으며, 주된 강의 분류와 `generated` 문제은행은 유지합니다.
- 새 필기본에서 보완한 문항도 원래 강의 분류에 넣습니다. 사용자 요청에 따라 `2026 필기본 보완` 같은 판본·업데이트별 분류나 태그를 따로 만들지 않습니다. 강의명·학습 주제와 `전범위 통합` 태그는 유지합니다.
- 게시된 문항을 개선할 때에는 가능한 한 기존 문항 ID와 정답 위치를 보존하고, 수정 범위와 정답 대응을 다시 검증합니다. 족보 원문 문제은행과는 별도로 관리합니다.

## 검증된 문제 묶음 추가

JSON, TXT, Markdown, CSV 파일을 사용할 수 있습니다. 예:

```sh
node scripts/import-chat-bundle.mjs /absolute/path/new-questions.json --bank generated --dry-run
node scripts/import-chat-bundle.mjs /absolute/path/new-questions.json --bank generated
```

정답표가 없는 실제 기출은 출처가 있을 때만 명시적으로 허용합니다.

```sh
node scripts/import-chat-bundle.mjs /absolute/path/past-questions.json --bank past --allow-unconfirmed
```

스크립트는 새 문제를 `data/chat-questions.js`에 저장합니다. 이 모듈은 앱의 공유 문제은행에 연결되어 있으며, 게시하면 다른 브라우저에서도 같은 추가 문제를 받습니다. 기존 원본 `past-*`, 기존 생성문제 `seed-*` ID는 덮어쓰지 않습니다. 새 문제 ID는 종류·분류·본문·보기의 내용으로부터 안정적으로 생성되어, 같은 문제를 중복 반영해도 기록 ID가 바뀌지 않습니다. 이미 반영한 채팅 문제를 수정하려면 `--replace-existing`을 명시합니다.

## GitHub Pages 게시

이 사이트는 공개 저장소 `tra030303/medical-microbiology-quiz`의 `immunote/` 폴더에 게시합니다.

- 사이트: https://tra030303.github.io/medical-microbiology-quiz/immunote/
- 소스: https://github.com/tra030303/medical-microbiology-quiz/tree/main/immunote
- 기존 저장소 루트의 미생물학 사이트와 Pages 설정은 유지합니다.

전체 작업 소스에서는 다음 명령으로 검증하고 게시용 정적 파일을 만듭니다.

```sh
npm test
node scripts/build-github-static.mjs
```

`outputs/github-static/`의 파일을 원격 저장소의 `immunote/` 아래에 반영하면 기존 Pages 배포가 갱신합니다. 업로드 경로와 체크섬은 `outputs/github-static-upload-manifest.json`에 기록됩니다. 인증정보, 원본 PDF, 사용자별 학습 기록은 게시하지 않습니다.

원문 그림은 필요한 문항을 열 때만 불러오는 `data/scan-packs/` 모듈과 `data/scan-index.js`로 게시합니다. 작업 소스에 WebP 원본이 있으면 빌드가 묶음을 다시 만들고, 원격 저장소에서 내려받은 소스에 이미 묶음이 있으면 그대로 보존합니다.

게시용 채팅 문제는 `data/chat-question-packs/`의 작은 모듈로 나누고 `data/chat-questions.js`에서 합칩니다. 문항 ID·내용·순서는 작업 소스와 같습니다. 게시할 때는 업로드 manifest에서 달라진 문제 모듈과 진입 파일·검토 의견을 함께 반영합니다. 가져오기 스크립트는 같은 `CHAT_QUESTIONS` 내보내기를 읽으며, 다음 빌드가 게시용 모듈을 다시 만듭니다.

## 문제 업데이트와 학습 기록

게시된 문제 데이터는 사이트를 새로 열거나 새로고침하면 받을 수 있습니다. 사이트에 게시하는 문제와 개인 학습 기록은 별개입니다. 풀이·오답·북마크는 현재 브라우저에 저장되며, 기존 문제의 ID가 유지되면 그 기록도 이어집니다. 다른 브라우저나 기기로 기록을 옮길 때는 백업·복원을 사용합니다.

교정 의견이 추가되더라도 기출의 원문 답안과 assistant의 의견을 같은 값으로 합치지 않습니다. 의견에 근거가 부족한 경우에는 단정적인 정답 변경 대신 확인이 필요하다는 설명을 표시합니다.

## 정답 검토 표시

`data/review-notes.js`는 문항 ID별 별도 검토 기록입니다. `originalAnswers`는 족보 원답이고, `suggestedAnswers`는 근거가 있을 때만 제시하는 검토상 권고 답입니다. 이 파일을 추가하는 것만으로 채점 정답을 바꾸지 않습니다. 정답 화면은 원답, 현재 채점 기준이 다른 경우의 안내, AI 검토 의견·근거·확실성·검토일을 구분합니다. 원문 정답이 없는 문항에 사용자가 답을 등록해도 그것을 원문 답안으로 표시하지 않습니다.

## 게시 위치와 이후 업데이트

사용자 요청에 따라 별도 저장소 대신 기존 공개 저장소의 `immunote/` 폴더를 사용합니다. 이후에도 이 채팅에 강의록·족보·새 문제를 첨부하고 업데이트를 요청하면, assistant가 내용을 검토하여 같은 저장소와 사이트 주소에 반영합니다. 채팅 첨부 자체를 감시하는 자동 서비스는 아니며 각 업데이트 요청을 assistant가 처리합니다.

## OX 기본 개념 문제

사용자 요청에 따라 OX는 두 객관식 은행과 구분합니다. OX는 `data/ox-index.js`의 강의록 출처와 `data/ox-questions.js`·`data/ox-packs/`의 문항으로 관리하며, 객관식 가져오기 스크립트에 넣지 않습니다. 같은 강의의 분할·수정본을 중복으로 세지 않고 강의당 30~50문항의 짧은 기본 개념을 작성합니다. 기존 OX 문항을 수정할 때는 ID와 참·거짓 대응을 보존·검증합니다.

사이트의 OX 메뉴에는 강의별 분류 없이 순서대로 풀기·전체 섞어 풀기를 제공합니다. 강의명은 해설의 출처로 남깁니다. 오답은 `오답 노트 → OX 오답`에 모으며 최근 답안을 기준으로 표시합니다. OX 답안·풀이·이어 풀기 위치는 기존 객관식 기록과 분리된 저장 상태의 `ox`에 보관하고 백업·복원에 포함합니다. 예전 백업과 객관식 기록의 호환성을 유지합니다.
